# 내 주변 빈 급속충전소 — 설계

작성일: 2026-11-19

## 1. 왜 하는가

ChargeFlow는 지금 "고속도로 휴게소가 붐빌 때 IC 밖 충전소로 우회할지"만 돕는다.
콘솔 지표(2026-08-01 ~ 11-18, 이용자 171명)는 이렇다.

- 50대 27%, 60대 이상 20%, 40대 15%. 안드로이드 77%.
- 주간 이용자 22명 → 1~7명으로 감소. 매주 이용자의 대부분이 신규.
- 1주 뒤 재방문 3%.
- 유입은 토스 안 탐색(전체탭·기타)이 대부분. 고속도로 위에서 여는 사람이 아니다.
- 최근 14일: 홈 39회 → 휴게소 상세 12회 → 길찾기 1회. 즐겨찾기 0.

앱이 쓸모 있는 순간(장거리 주행 중)이 1년에 몇 번뿐이라, 올 수 있는 사람 자체가 적다.
이용자 수를 늘리는 것이 목표이므로, 대상을 "장거리 가는 날"에서 "충전하는 모든 날"로 넓힌다.

## 2. 목표 · 하지 않는 것 · 실패 조건

**목표**
- 앱을 열면 버튼을 누르지 않아도 내 위치와 지도가 뜨고, 주변 급속충전소의 지금 빈 대수가 보인다.
- 50·60대가 설명 없이 쓸 수 있다: 큰 글씨, 적은 선택지, 길찾기까지 두 번 이내의 터치.
- 기존 고속도로 기능은 그대로 남는다.

**하지 않는 것 (이번 범위 밖)**
- 완속 충전기
- 앱 안 결제, 충전 카드·로밍 안내
- 이용자 후기·고장 제보
- 경로 계획(차종별 배터리 계산), 예약
- 티맵 등 다른 내비 연동 (지금처럼 카카오맵 길찾기 링크만)
- 주변 충전소 즐겨찾기·알림

**실패 조건 (동작해도 실패로 본다)**
- 첫 화면에서 위치 권한을 거절한 사람이 아무것도 못 하는 막다른 화면을 본다.
- 실제로는 꽉 찼거나 고장인 곳을 "비어 있어요"로 보여 준다. 오래된 상태는 빈 곳으로 세지 않는다.
- 지방 이용자가 빈 지도를 본다(일부 지역만 데이터가 있는 상태).
- 기존 공유 링크(`intoss://chargeflow/rest-area/:id`)와 고속도로 화면이 깨진다.
- 공공데이터 일일 호출 한도(1,000회)나 DB 볼륨(500MB)을 넘겨 폴러가 멈춘다.

## 3. 제약

- 공공데이터(한국환경공단 EvCharger) 개발계정 한도 1,000회/일. 지금 폴러는 10분 크론 기준 하루 약 450회를 쓴다.
- Railway Postgres 볼륨 500MB. 과거에 한 번 포화된 적이 있다(`poll_charger_status._skip_query_stats` 참고).
- 로컬 개발은 SQLite. PostGIS 같은 확장에 의존하지 않는다.
- 프론트는 앱인토스 미니앱(React + TDS). `frontend/AGENTS.md`의 하드 규칙을 지킨다(본문 15px 이상, 터치 타깃 44px 이상, 상단 네비 직접 그리지 않기 등).
- 지도는 이미 쓰는 카카오맵(`frontend/src/lib/kakao.ts`)을 쓴다.
- 앱 식별자 `chargeflow`는 바꿀 수 없다.

## 4. 검토한 방식

| 방식 | 내용 | 결론 |
|---|---|---|
| 전국 급속을 서버에 쌓기 | 폴러가 받는 전국 상태에서 급속 충전기 전부를 저장하고, 요청한 위치 주변만 꺼내 준다 | **채택** |
| 열 때마다 공공데이터 조회 | 서버에 쌓지 않고 요청마다 지역 단위로 조회 | 한도 1,000회/일에 바로 걸리고 응답이 느리다 |
| 수도권만 먼저 | 일부 지역만 저장 | 다른 지역 이용자가 빈 지도를 본다(실패 조건) |

채택 이유: `getChargerStatus` 증분 피드는 이미 전국 단위로 오고, 폴러가 추적 대상 statId만 골라 저장하고 있다(`_apply_items`의 `tracked` 필터). 추가 호출 없이 저장 범위만 넓히면 된다. 방식 선택은 이용자가 맡겨서 작성자가 골랐다.

홈 화면 모양은 이용자가 시안을 보고 직접 골랐다: **지도 + 가까운 순 목록**(시안 `.superpowers/brainstorm/1339-1795047448/content/home-map-v2.html`의 2번). "결론 하나만 크게" 안과 "지도 + 가장 가까운 한 곳" 안은 선택되지 않았다.

## 5. 이용자가 정한 것

- 방향: 평소 충전까지 넓힌다. 이용자 수 증가가 목표다.
- 급속(50kW 이상)만 다룬다.
- 첫 화면부터 바로 내 위치와 지도를 띄운다. 쉽고 직관적이어야 한다.
- 홈은 지도 + 가까운 순 목록.
- 한글 앱 이름은 새 화면 출시에 맞춰 바꾼다.

## 6. 화면 설계

### 6.1 새 홈 (`/`)

```
┌──────────────────────────┐
│ [급속 · 빈 곳 3곳]        │  ← 지도 위 요약 칩
│        (3대)              │
│  (꽉 참)    ● 내 위치      │  ← 핀: 빈 대수가 적힌 알약, 꽉 찬 곳은 회색·작게
│  (1대)        (2대) [내 위치]│  ← 내 위치로 돌아오는 버튼
├──────────────────────────┤
│ 영통 공영주차장        3대 │
│ 약 1.2km · 100kW          │
│ 광교 마트 주차장       2대 │
│ 약 2.1km · 200kW          │
│ 망포역 환승주차장      1대 │
│ 약 3.4km · 100kW          │
│ 14시 32분 확인            │
├──────────────────────────┤
│ 고속도로 가는 날이에요  휴게소 보기 │
└──────────────────────────┘
```

- 지도가 화면 위쪽 절반 남짓, 그 아래 목록.
- 목록은 **빈 충전기가 있는 곳만**, 가까운 순으로 3곳. 더 있으면 "더 보기"로 펼친다. 꽉 찬 곳·이용 불가인 곳은 지도에 회색 핀으로만 보인다.
- 거리는 직선거리이고 "약"을 붙인다(기존 화면의 표기 규칙과 같다). 주행 시간은 보여 주지 않는다.
- 충전소마다 상태를 마지막으로 확인한 때를 보여 준다. 30분 이내면 목록에서는 생략하고, 그보다 오래됐으면 줄 설명에 "2시간 전 확인"처럼 붙인다. 상세 시트에는 항상 보여 준다. (위 그림의 "14시 32분 확인"은 목록을 받아 온 시각이다.)
- 핀이나 목록 줄을 누르면 아래에서 상세 시트가 올라온다: 이름, 주소, 운영사, 출력, 운영 시간, 커넥터, 빈 대수/전체, 길찾기 버튼. 기존 `StationSheet`를 재사용하거나 맞게 고친다.
- 지도 위에 "내 차 충전 규격" 버튼 하나. 기존 `ConnectorPicker`·`useConnector`를 그대로 쓴다. 고른 규격에 맞는 곳만 보인다.
- 화면이 보이는 동안 60초마다 조용히 새로 받는다(기존 휴게소 상세와 같은 방식).
- 글씨: 본문 15px 이상, 충전소 이름 17px 이상, 빈 대수 20px 이상. 핀 글씨 15px 이상.

### 6.2 위치 흐름

- 앱을 열면 바로 위치를 가져온다(`getLocation()`; 권한이 없으면 권한 요청이 뜬다).
- 전에 받아 둔 위치가 있으면 그 위치로 지도를 먼저 그리고, 새 위치가 오면 옮긴다. 마지막 위치는 기기에만 저장한다.
- **거절·실패 시**: 시·도 목록을 보여 주고, 고르면 그 지역 중심으로 지도를 띄워 검색한다. "위치 켜고 다시 찾기" 버튼도 함께 둔다.
- 지도를 손으로 옮기면 "이 위치에서 찾기" 버튼이 나타나고, 누르면 지도 중심으로 다시 찾는다. (거절 시 지역 선택과 같은 "지도 중심 검색"을 쓴다. 작성자 판단.)

### 6.3 빈 곳이 없을 때

- 서버가 반경을 5km → 10km → 20km → 30km로 넓혀 가며, 빈 곳이 3곳 이상 나오는 첫 반경에서 멈춘다.
- 30km까지 빈 곳이 하나도 없으면 "30km 안에 지금 빈 급속충전소가 없어요"와 함께 꽉 찬 곳 중 가까운 곳을 목록으로 보여 준다(막다른 화면 금지).
- 30km 안에 충전소 자체가 없으면 그렇게 말하고 고속도로 화면으로 가는 길만 남긴다.
- (구현) 빈 곳이 없을 때 목록은 문구와 맞춘다: 충전 중(꽉 참)인 곳이 있으면 그곳만 "충전 중인 곳을 가까운 순서로 보여 드려요"로 보여 주고, 이용 불가만 있으면 "{반경}km 안에 지금 쓸 수 있는 급속충전소가 없어요 / 점검 중이거나 연결이 끊긴 곳만 있어요"로 그곳들을 보여 준다. 지도에는 지금처럼 모두 회색 핀으로 그린다.
- (구현) 결과가 비었는데 서버가 상태 정보를 받지 못하고 있으면(`feed_stale`) "충전소가 없어요" 대신 "지금 충전소 정보를 받지 못하고 있어요 / 잠시 후 다시 확인해 주세요"와 "다시 시도" 버튼을 보여 준다. 확인 시각 줄은 숨기고, 1분마다 조용히 다시 받아 정보가 돌아오면 저절로 바뀐다.

### 6.4 고속도로 화면

- 지금의 `HomePage`를 새 경로(예: `/highways`)로 옮긴다. 내용과 기능은 그대로.
- 새 홈 맨 아래 한 줄 "고속도로 가는 날이에요 · 휴게소 보기"로 들어간다.
- `/highway/:code`, `/rest-area/:id`, `/trip` 경로는 바꾸지 않는다.

### 6.5 기록(Analytics)

화면 `nearby`, 클릭 `nearby_station_open`(from: pin|list), `nearby_directions`, `nearby_more`, `nearby_search_here`, `nearby_location_denied`, `nearby_region_pick`, `nearby_open_highway`. 기존 `logScreen`·`logClick`을 쓴다. 성공 지표는 주간 이용자 수와 `nearby` → `nearby_directions` 비율이다.

## 7. 서버 설계

### 7.1 충전소 목록(카탈로그)

- 전국 급속 충전소를 **새 테이블**에 넣는다(statId가 고유 키). 기존 `ChargingStation`에는 넣지 않는다. (작성자 판단.)
  - 이유: `Procfile`이 배포 때마다 `loaddata chargeflow_data.json`을 돌리고, `build_catalog`는 IC 매핑이 없는 충전소를 지운다(202행 부근). 같은 테이블에 전국분을 섞으면 pk·`source_api_id` 충돌로 배포가 실패하거나 전국분이 지워질 수 있다.
  - 기존 fixture, `ChargingStation`, `NodeStationMapping`, `HighwayNodeCharger`, `build_catalog`는 건드리지 않는다. IC 우회 충전소가 새 테이블에도 들어가는 중복은 허용한다.
- "급속"의 기준: 충전기 출력(`output`) **50kW 이상**. 기존 `build_catalog.FAST_KW = 50`과 같다. 충전소에 그런 충전기가 하나라도 있으면 대상이고, 빈 대수·전체 대수는 50kW 이상 충전기만 센다.
- 일반 이용자가 못 쓰는 곳은 뺀다. 기존 우회 매핑(`build_catalog` 406~408행)과 같은 규칙: 이용 제한(`limitYn=Y`), 공동주택(`kind=H0`), 삭제(`delYn=Y`), 고속도로 휴게소 안 충전소(`kindDetail=C001` 또는 이름에 "휴게소"). 휴게소 충전소는 고속도로 화면에서 다룬다.
- 채우는 방법: `getChargerInfo` 전국 스캔(약 60회 호출, `build_catalog`에 같은 스캔이 있다)을 **서버에서 주기적으로 돌리는 명령**으로 만든다. 주기는 하루 1회 이하로 하고, 하루 총 호출이 800회를 넘지 않게 한다. (작성자 판단.)
- 이 스캔은 충전기별 출력과 상태를 함께 주므로, 전국 급속 충전기의 상태 기준선 역할도 한다.

### 7.2 충전기 상태

- 폴러의 추적 대상을 "휴게소 + IC 우회 충전소"에서 "+ 새 테이블의 전국 급속 충전소"로 넓힌다.
- 증분 피드(`getChargerStatus`)에는 출력·`chgerType`이 없다. 그래서 전국분의 `ChargerState` 줄은 **전국 스캔이 50kW 이상 충전기에 대해서만 만들고**, 증분 피드는 이미 있는 줄만 갱신한다. 스캔 사이에 새로 생긴 충전기는 다음 스캔까지 무시한다. 휴게소·IC 우회 충전소의 기존 동작(증분 피드가 줄을 만든다)은 그대로 둔다.
- `ChargerState`는 충전기당 한 줄이라 전국 급속을 다 넣어도 수만 줄 수준으로 예상한다. **구현 첫 단계에서 실제 급속 충전기 수를 세고**, 예상 용량을 계산해 500MB의 절반을 넘으면 멈추고 알린다.
- `ChargerStatusLog`(2시간 보관, 회전율 계산용)는 지금처럼 **휴게소·IC 우회 충전소만** 남긴다. 전국분은 쌓지 않는다.
- `_apply_items`는 매 주기 추적 대상 전체를 메모리에 올린다. 대상이 수만 줄로 늘어나므로, 이번 응답에 들어온 statId만 읽도록 바꾼다.
- 휴게소 혼잡도 계산·알림 로직은 바꾸지 않는다.

### 7.3 빈 대수 판정

충전소 하나에 대해, 50kW 이상 충전기만 세어:

- **빈 곳**: `stat = 2`(충전가능)이고 상태가 오래되지 않은 충전기 수.
- **충전 중**: `stat = 3`.
- **이용 불가**: `stat` 1·4·5(통신이상·운영중지·점검중).
- **오래됨의 기준**: 충전기의 `stat_updated_at`(API `statUpdDt`)으로 잰다. 시작값은 12시간으로, 기존 우회 충전소 규칙(`congestion.STATION_STALE`)과 같다. 기존 30분 기준(`STALE_MINUTES`)은 폴러 집계 시각에 대한 것이라 충전기 단위에는 맞지 않는다. (작성자 판단.)
  - 10분 증분 피드는 전국 1만 5천 건 안팎이라, 가만히 비어 있는 충전기는 몇 시간씩 새 보고가 없을 수 있다. 기준을 짧게 잡으면 지도가 비고, 길게 잡으면 낡은 "빈 곳"이 보인다.
  - **구현 첫 단계에서 실측한다**: 전국 스캔 직후와 몇 시간 뒤에, 50kW 이상 충전기 중 `statUpdDt`가 30분·2시간·12시간 안인 비율을 센다. 2시간 기준으로도 80% 이상이 남으면 2시간으로 줄이고, 아니면 12시간을 유지한다. 12시간으로도 절반이 안 남으면 멈추고 알린다.
  - **실측 결과(2026-11-19, 전국 급속 충전소 18,250곳·충전기 37,547대, 로컬 DB 증가 약 7MB)**: `statUpdDt`가 30분 안 27%, 2시간 안 36%, 12시간 안 54%, 24시간 안 75%, 3일 안 85%. 12시간보다 오래된 충전기는 대부분 `stat=2`(충전가능)였다. 12시간 기준이면 충전소의 36%가 지도에서 빠진다. **이용자가 24시간으로 정했다.** 위 규칙의 12시간은 24시간으로 대체한다.
  - 낡은 정보로 인한 헛걸음을 줄이기 위해, 충전소마다 가장 최근 확인 시각을 응답에 넣고 화면에 "N분 전 확인"으로 보여 준다(6.1).
- 기준보다 오래된 충전기는 "정보 없음"으로 보고 빈 곳에 넣지 않는다.
- 충전소 표시: 빈 곳 1대 이상 → "N대", 빈 곳 0이고 충전 중이 있음 → "꽉 참", 전부 이용 불가 → "이용 불가", 전부 정보 없음 → 주변 검색 결과에서 뺀다.

### 7.4 주변 검색 API

`POST /api/v1/stations/nearby/` — 본문 `{"lat": 37.251, "lng": 127.071, "connector": "combo"}`

- 조회지만 POST를 쓴다. 좌표가 주소(쿼리)에 들어가면 호스팅·프록시 접속 기록에 남기 때문이다. 프론트는 좌표를 소수 셋째 자리(약 100m)로 반올림해 보낸다. (작성자 판단.)

- 반경을 6.3의 순서로 넓힌다. 위·경도 범위로 먼저 거르고 직선거리(기존 `_haversine_km`)로 정렬한다. 새 테이블의 위·경도에 인덱스를 둔다.
- 응답: 검색에 쓴 반경, 받아 온 시각, 충전소 목록(가까운 순, 최대 30곳). 충전소마다 id, 이름, 주소, 위·경도, 거리, 빈 대수·충전 중·이용 불가·전체, 최대 출력, 운영사, 운영 시간, 커넥터, 표시 상태, 상태를 마지막으로 확인한 시각. 그리고 `feed_stale`(참/거짓): 목록이 비었을 때만 계산하며, 활성 충전소가 없거나 폴러의 마지막 상태 수신·스캔의 마지막 반영 중 최근 것이 24시간(`PUBLIC_STALE`)보다 오래됐으면 참. 목록이 있으면 언제나 거짓(추가 조회 없음).
- `connector`가 오면 맞는 커넥터가 있는 충전소만. 커넥터 정보가 없는 충전소는 포함한다(기존 `fits` 규칙과 같다).
- 받은 좌표는 저장하지도, 로그에 남기지도 않는다.
- 좌표가 없거나 한국 범위를 벗어나면 400.

## 8. 출시 순서

1. 서버: 카탈로그 명령 + 폴러 확장 + 주변 검색 API 배포. 운영 DB에 전국 급속이 채워지고 용량·호출량이 한도 안인지 하루 이상 지켜본다.
2. 프론트: 새 홈 번들 검수 요청·출시.
3. 앱 정보: 번들 출시와 맞춰 이름·부제·상세 설명·검색 키워드를 바꿔 검토 요청.
   - 이름 후보: "전기차 빈 충전소 찾기"(공백 제외 9자). 최종 문구는 검토 요청 전에 이용자에게 확인받는다.
   - 검색 키워드(최대 10개)는 지금 6개가 모두 고속도로 쪽이다. "내 주변 충전소", "급속충전", "충전소 찾기" 같은 평소 검색어를 더한다.
   - 스크린샷도 새 홈 기준으로 바꾼다.

2·3번의 검수·검토 요청은 밖으로 나가는 행동이므로 그때 이용자 승인을 받는다.

## 9. 테스트

- 서버: 빈 대수 판정(상태별, 30분 경과, 급속만 세기), 반경 확장, 커넥터 필터, 좌표 검증, 폴러가 전국 급속을 반영하면서 이력은 휴게소만 남기는지. 기존 `python manage.py test chargeflow`에 더한다.
- 프론트: 브라우저 개발 환경(devtools mock)에서 권한 허용·거절·실패, 빈 곳 없음, 충전소 없음 화면을 각각 확인한다.

## 10. 만드는 사람에게 맡기는 것

- 새 경로 이름, 컴포넌트·파일 구성, 지도 컴포넌트를 새로 만들지 `RestAreaMap`을 일반화할지.
- 카탈로그 명령을 `build_catalog`에서 떼어 낼지 옵션으로 넣을지, 크론을 어떻게 걸지.
- 핀이 많을 때 지도에 그릴 개수 상한과 겹침 처리.
- 시·도 목록의 중심 좌표 값.
- 위치 권한을 묻기 전 안내 문구가 앱인토스 정책상 필요한지(개발자센터 문서로 확인).
- 화면 문구의 최종 다듬기(해요체 유지).
